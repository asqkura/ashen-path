# カード設計まとめ

## 目的
- 属性の役割とキーワード能力を1か所で確認できるようにする
- 新しいカードを作るときの判断基準をそろえる
- 既存カードの見直し方針を整理する

## 現在の前提
- 属性は `無 / 炎 / 氷 / 風 / 光 / 闇`
- 共通ルールとしての `Break` は一旦外している
- カードは `JSON` 管理前提で、今後はキーワードを軸に整理していく

## 戦闘システムデザイン

### 基本構造
- 1対1のターン制カードバトル
- プレイヤーはデッキを編成して戦闘に入る
- 戦闘中は手札からカードを1枚ずつ使い、状況更新後に次の1枚を選ぶ

### リソース
- プレイヤーは `SP` を消費してカードを使う
- `SP` はターン開始時に一定量回復する
- 手札は毎ターン全破棄せず、ターン開始時に固定枚数をドローする
- 1ターンに使えるカードは最大 `3` 枚

### 勝ち筋
- 基本はカードの組み合わせと属性の個性で押し切る
- 炎は重い1枚の打点を育てる
- 氷は凍結スタックで敵行動を止める
- 風は回転力と手数で差を作る
- 光は次カード強化で流れを整える
- 闇はHP喪失を条件に高リターンを狙う

### 現在の方針
- `Break` は一旦外し、属性ごとの役割が直接立つ形を優先する
- 強すぎる共通ルールより、カード同士の噛み合いで戦術を作る
- キーワードはまず表示整理のために定義し、後から実装へ落とし込む

### 今後詰めるポイント
- 敵行動の個性づけ
- キーワードごとの実装ルール
- デッキ編集後の成長導線
- カードパワーの再調整
- 敵データと行動テーブルの拡張

## 属性の役割

### 無属性
- 役割: 安定
- 方向性:
  - 低コスト
  - 基本ダメージ
  - 汎用支援
  - 手札事故の保険

### 炎
- 役割: 高火力
- 方向性:
  - 重めコスト
  - 1枚あたりのリターンが大きい
  - `熾火` で後続の炎火力を育てる
  - 使い切りや切り札向き

### 氷
- 役割: 制御
- 方向性:
  - `凍結` を積んで敵行動を止める
  - 中火力
  - テンポ妨害
  - 堅実で安定した干渉

### 風
- 役割: 手数
- 方向性:
  - 軽いコスト
  - ドロー
  - 連続使用
  - 回転力で押す

### 光
- 役割: 支援
- 方向性:
  - `啓示` で次の `祝福` を開く
  - `祝福` で次のカードを強化する
  - 補助寄りだが、手順で流れを作る

### 闇
- 役割: リスクと爆発力
- 方向性:
  - HP喪失や手札損失と相性が良い
  - 条件達成で大きい見返り
  - 高火力
  - 危険だが最大値が高い

## キーワード能力

### 熾火 X
- 属性: 炎
- 定義:
  - このカードを使った後、このバトル中、自分の炎カードのダメージを `+X`
- 方針:
  - 基本は `SP3` 以上の重い炎カードに載せる
  - 軽い炎に配りすぎない

### 凍結 X
- 属性: 氷
- 定義:
  - 敵に凍結を `X` 付与する
  - 凍結が一定値まで溜まると、次の敵行動をスキップして凍結をリセットする
- 方針:
  - 小さく積んで止める
  - 発動時は全消費前提
  - ハメにならないようしきい値は慎重に決める

### 追風
- 属性: 風
- 定義:
  - このターン最初の風カードなら、カードを1枚引く
- 方針:
  - 風の回転力は残す
  - 無条件ドローにはしない
  - 少量採用の入れ得にならないようにする

### 啓示
- 属性: 光
- 定義:
  - 次に使うカードが `祝福` を持っていれば、その追加効果を発動可能にする
- 方針:
  - 光の準備札に載せる
  - 単体では大きな見返りにしない

### 祝福 X
- 属性: 光
- 定義:
  - 直前のカードで `啓示` を得ていた場合に発動し、次に使うカード1枚のダメージを `+X`
- 方針:
  - 単体でただの汎用強化にしない
  - `啓示 -> 祝福 -> 次のカード` の流れで使う

### 協約
- 属性: 闇
- 定義:
  - このターン中にHPを失っていたら、追加効果を発動する
- 方針:
  - 単なるHPコストの言い換えにしない
  - HP喪失を参照する共通条件として扱う

### 消滅
- 属性: 共通
- 定義:
  - 使ったらそのバトル中は除外される

## デザイン上の注意
- `Break` 前提のカードは作り直し対象と考える
- キーワードはただの数値言い換えにしない
- 属性ごとの勝ち筋が被りすぎないようにする
- 便利効果は `追風` のように入れ得になりやすいので慎重に配る
- 光は `啓示` と `祝福` の2段構えにして、無属性支援の単純強化と分ける

## 戦闘システム改修案

### いま感じている問題
- 複数枚をまとめて選んで同ターン中に一気に解決するため、順番効果がただの効率札になりやすい
- 手札を不足分補充する現在ルールだと、ドローが強すぎて風の個性がシステムの穴を突く形になりやすい
- 敵行動が単調で、属性ごとの対応力や温存判断が立ちにくい

### 改修方針
- カード思想に合わせて、1ターン中の意思決定を増やす
- `何を使うか` だけでなく `何を残すか` `どの順番で使うか` に意味を持たせる
- 属性キーワードがその場限りの数値効率ではなく、戦況に影響する形へ寄せる

### 新しい基本ループ
1. ターン開始時に固定枚数ドローする
2. 敵の次行動予告を見る
3. カードを1枚使う
4. 状況更新後、残りの `SP` と使用枚数上限の範囲で次の1枚を選ぶ
5. プレイヤーが終了したら敵行動へ進む

### 具体的な変更案

#### 1枚ずつ使う
- 先に複数枚をまとめて確定する方式をやめる
- `1枚使う -> 状態更新 -> 次を選ぶ` へ変える
- `祝福` `凍結` `協約` のような順番・条件系を活かしやすくする

#### ターン開始ドローを固定化する
- 毎ターンの手札補充を `不足分まで補充` ではなく `固定枚数ドロー` にする
- 仮案:
  - 手札上限 `5`
  - ターン開始時ドロー `2`
- これでドローの価値を明確にし、風の立ち位置を調整しやすくする

#### 1ターンの使用枚数上限を設ける
- `SP` とは別に、1ターンで使えるカード枚数を `2〜3枚` に制限する
- 軽いカードの連打だけで最適化されるのを防ぐ
- 温存判断を生みやすくする

#### 敵行動予告を導入する
- 敵は次に何をするかを事前に見せる
- 例:
  - 強攻撃
  - 連撃
  - 溜め
  - 防御
- 氷や光、闇の対応力に意味を持たせる
- 行動はコード直書きではなく、敵データごとの重みテーブルで差し替えられる形を目指す

#### 戦場状態を見える化する
- プレイヤー側:
  - `熾火`
  - `祝福`
  - `協約` の条件達成状態
- 敵側:
  - `凍結` スタック
  - 次行動予告
- 状態が見えることで、カード選択の理由が明確になる

### 属性ごとの噛み合い
- 炎:
  - `熾火` を積みながら重い1枚を通す
- 氷:
  - `凍結` スタックで敵行動を止める
- 風:
  - 条件付きの回転力やテンポ操作で差を作る
- 光:
  - `祝福` で次の1枚を支える
- 闇:
  - HP喪失を参照する `協約` を狙って強い見返りを取る

### 期待する効果
- カードの順番に意味が出る
- 温存か使用かの判断が生まれる
- 風のドローが雑に強い状態を避けやすくなる
- 属性ごとの役割がシステム上でも立ちやすくなる
