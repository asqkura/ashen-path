# カード設計まとめ

## 目的
- 属性の役割とキーワード能力を1か所で確認できるようにする
- 新しいカードを作るときの判断基準をそろえる
- 既存カードの見直し方針を整理する

## 現在の前提
- 属性は `無 / 炎 / 氷 / 風 / 光 / 闇`
- 共通ルールとしての `Break` は一旦外している
- カードは `JSON` 管理前提で、今後はキーワードを軸に整理していく

## 戦闘システムデザイン

### 基本構造
- 1対1のターン制カードバトル
- プレイヤーはデッキを編成して戦闘に入る
- 戦闘中は手札から複数カードを選び、順番に解決する

### リソース
- プレイヤーは `SP` を消費してカードを使う
- `SP` はターン開始時に一定量回復する
- 手札は毎ターン全破棄せず、使ったカードだけ減り、不足分だけ補充する

### 勝ち筋
- 基本はカードの組み合わせと属性の個性で押し切る
- 炎は重い1枚の打点を育てる
- 氷は凍結スタックで敵行動を止める
- 風は回転力と手数で差を作る
- 光は次カード強化で流れを整える
- 闇はHP喪失を条件に高リターンを狙う

### 現在の方針
- `Break` は一旦外し、属性ごとの役割が直接立つ形を優先する
- 強すぎる共通ルールより、カード同士の噛み合いで戦術を作る
- キーワードはまず表示整理のために定義し、後から実装へ落とし込む

### 今後詰めるポイント
- 敵行動の個性づけ
- キーワードごとの実装ルール
- デッキ編集後の成長導線
- カードパワーの再調整

## 属性の役割

### 無属性
- 役割: 安定
- 方向性:
  - 低コスト
  - 基本ダメージ
  - 汎用支援
  - 手札事故の保険

### 炎
- 役割: 高火力
- 方向性:
  - 重めコスト
  - 1枚あたりのリターンが大きい
  - `熾火` で後続の炎火力を育てる
  - 使い切りや切り札向き

### 氷
- 役割: 制御
- 方向性:
  - `凍結` を積んで敵行動を止める
  - 中火力
  - テンポ妨害
  - 堅実で安定した干渉

### 風
- 役割: 手数
- 方向性:
  - 軽いコスト
  - ドロー
  - 連続使用
  - 回転力で押す

### 光
- 役割: 支援
- 方向性:
  - 次のカードを強化する
  - 補助寄り
  - 光そのものの個性はカード個別効果で後から詰める

### 闇
- 役割: リスクと爆発力
- 方向性:
  - HP喪失や手札損失と相性が良い
  - 条件達成で大きい見返り
  - 高火力
  - 危険だが最大値が高い

## キーワード能力

### 熾火 X
- 属性: 炎
- 定義:
  - このカードを使った後、このバトル中、自分の炎カードのダメージを `+X`
- 方針:
  - 基本は `SP3` 以上の重い炎カードに載せる
  - 軽い炎に配りすぎない

### 凍結 X
- 属性: 氷
- 定義:
  - 敵に凍結を `X` 付与する
  - 凍結が一定値まで溜まると、次の敵行動をスキップして凍結をリセットする
- 方針:
  - 小さく積んで止める
  - 発動時は全消費前提
  - ハメにならないようしきい値は慎重に決める

### 追風
- 属性: 風
- 定義:
  - このターン最初の風カードなら、カードを1枚引く
- 方針:
  - 風の回転力は残す
  - 無条件ドローにはしない
  - 少量採用の入れ得にならないようにする

### 祝福 X
- 属性: 光
- 定義:
  - 次に使うカード1枚のダメージを `+X`
- 方針:
  - 一旦はシンプルな次カード強化で整理する
  - 無属性支援との差別化はカード個別効果で詰める

### 協約
- 属性: 闇
- 定義:
  - このターン中にHPを失っていたら、追加効果を発動する
- 方針:
  - 単なるHPコストの言い換えにしない
  - HP喪失を参照する共通条件として扱う

### 消滅
- 属性: 共通
- 定義:
  - 使ったらそのバトル中は除外される

## デザイン上の注意
- `Break` 前提のカードは作り直し対象と考える
- キーワードはただの数値言い換えにしない
- 属性ごとの勝ち筋が被りすぎないようにする
- 便利効果は `追風` のように入れ得になりやすいので慎重に配る
- `祝福` と無属性支援のように役割が近いものは、個別カードで差を付ける
